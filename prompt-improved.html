STEP 01What This Prompt Is For
▾

This prompt is for improving and standardising an existing resume or portfolio template that was previously redesigned. You will be given the current files. Your job is not to redesign the visual style — keep the existing look, fonts, and color palette. Instead you will:

  • Update data.json to match the universal standard schema defined in Step 2
  • Update index.html to render all standard sections, apply the theme from JSON, and follow the correct offline/online button logic
  • Update form.html to include all standard sections, add the theme color picker if missing, and ensure Load JSON repopulates every field
  • Fix any broken or inconsistent features (hamburger, offline buttons, preview, toast)
  • Add any sections this template is missing compared to the standard feature set

This applies equally to resume templates (CV-style, single-person focused) and portfolio templates (project-showcase focused, may include a works/gallery section). Treat them consistently — the same schema, the same features, the same rules.

Golden Rule

Do not change the visual design. The existing color scheme, fonts, layout, and aesthetic identity of the template must be preserved. All improvements are functional and structural — not cosmetic.

STEP 02Universal data.json Schema
▾

Every template — resume or portfolio — must use this exact top-level structure. Fields marked required must always be present. Fields marked optional should be included if the template has a section for them; they can be empty arrays or omitted entirely if truly unused.

KeyTypeStatusDescription
namestringRequiredFull name of the person. Used in page title, nav brand, hero, footer.
titlestringRequiredJob title or professional descriptor shown in the hero section.
aboutstring or string[]RequiredProfessional summary. Can be a single string or an array of paragraph strings.
themeobjectRequiredContains gradientStart, gradientEnd, accentColor. Applied as CSS variables on load.
contactobjectRequiredContains phone, email, address. Shown in hero chips and contact section.
profileobjectRequiredContains image (path to photo, e.g. "assets/profile.jpg") and eyebrow (short status label, e.g. "Open to Opportunities").
experiencearrayRequiredEach item: company, role, start, end, details (string[]). Bullet-point responsibilities.
educationarrayRequiredEach item: degree, institution, start, end, description (string).
skillsarrayRequiredEach item: name (string) and level (0–100 integer). OR grouped by category with an items array — pick whichever the template uses.
languagesarrayRequiredEach item: name (string) and level (0–100 integer).
referencesarrayRequiredEach item: name, role, phone, email.
projectsarrayOptionalEach item: name, description, liveUrl, codeUrl. Include for portfolio-style or developer templates.
awardsarrayOptionalEach item: date, title, institution, description.
statsarrayOptionalEach item: value (string, e.g. "6+") and label (string, e.g. "Years Experience"). Displayed as stat counters.
heroobjectOptionalFor templates with a separate hero image: description (tagline string) and image (path string).
footerobjectRequiredContains text (copyright string with {year} placeholder) and socials (array of { name, url } objects).
Consistency Rules
  • Always use name at the top level — never personalInfo.firstName + personalInfo.lastName or nested variants
  • Always use contact.phone, contact.email, contact.address — never flat top-level keys
  • Always use footer.socials for social links — never a top-level socialLinks array
  • Always use profile.image for the photo path — never personalInfo.photo or similar
  • The footer.text string must contain {year} which is replaced at runtime with new Date().getFullYear()
  • Skills can be flat ([{ name, level }]) or grouped ([{ category, items: [{ name, level }] }]) — choose based on the template's existing UI, but be consistent within the template

STEP 04index.html — What to Fix & Add
▾
Offline-Only Elements — Fix This First

Every element that should only appear when the site is opened locally as a file:// URL must have both of the following directly in the HTML:

  • class="offline-only"
  • style="display:none" as an inline attribute

This includes: the Load JSON button, the Edit nav link, and any mobile menu equivalents of those two. In CSS add .offline-only { display: none; } as a safety net. In JS, reveal them only if location.protocol === 'file:':

if (isLocal) document.querySelectorAll('.offline-only').forEach(el => el.style.display = '');

Never conditionally hide them — the default is always hidden; JS only shows them.

Data Loading & Theme
  • The render(data) function must read from the unified schema in Step 2 — update any field references that don't match (e.g. change data.personalInfo.firstName to data.name)
  • Always call applyTheme(data.theme) immediately after parsing the data
  • applyTheme must set --g1, --g2, --ac CSS variables and derive --ac-dim / --ac-glow using a hexAlpha(hex, alpha) helper
  • Also set document.body.style.background directly as an override
  • The #data= URL hash fallback must be present in the fetch catch block
  • Replace {year} in footer.text with new Date().getFullYear() when rendering
Sections to Add If Missing
  • References — render as two-column card grid (name, role, phone, email). Add to index.html and add a nav link
  • Languages — render as dot-bar indicators or pill list with level percentage
  • Footer — must show footer.text (with year replaced) and social icon links from footer.socials
  • Profile eyebrow — show profile.eyebrow as a small label above the name in the hero (e.g. "Open to Opportunities")
Navigation Consistency
  • The nav brand/logo must display data.name loaded dynamically — never hardcoded
  • Nav must include links to every section present: About, Experience, Education, Skills, Languages, References, Contact — plus optional sections if present
  • Hamburger: toggle .active on the button, toggle .open on the mobile dropdown, swap icon ☰ ↔ ✕, close on outside click, close on link tap
Page Title
  • Always set document.title = data.name + ' — Resume' (or '— Portfolio' for portfolio-style templates) inside the render function
STEP 05form.html — What to Fix & Add
▾
Theme Color Picker — Add If Missing

If the template does not already have a theme picker section, add it as a dedicated card between the Contact section and the first repeating section. It must contain:

  • 8 preset swatches — circular buttons with a gradient background and a small accent-color dot. Clicking applies the preset live to the page
  • 3 manual color pickers — input[type="color"] each paired with a synced hex text input for Gradient Start, Gradient End, and Accent Color
  • Live preview strip — a thin bar showing g1 → accent → g2, updating in real time as any picker changes
  • Selecting a preset marks it .active and deselects all others; manually changing any picker deselects all presets
  • All changes apply live to the form page background and accent CSS variables

The 8 presets must be a varied set — include both light and dark options if the template supports them, or all-light / all-dark if the template is specifically one or the other. Label them clearly.

Sections to Add If Missing
  • References — dynamic add/remove cards with fields: Name, Role, Phone, Email
  • Languages — dynamic add/remove with fields: Language name, Level (0–100 number input)
  • Footer & Socials — a card with Footer Text input and dynamic social link rows (platform dropdown + URL field)
  • Profile fields — inputs for Profile Image path and Eyebrow label (the short status string above the name)
Fix Load JSON

The loadJSON() function must be updated to match the unified schema. When a file is loaded it must:

  1. Clear all dynamic container elements (innerHTML = '')
  2. Populate all static fields: name, title, about, contact.phone, contact.email, contact.address, profile.image, profile.eyebrow, footer.text
  3. Re-run the add function for every item in: experience, education, skills, languages, references, footer.socials, and any optional arrays (projects, awards, stats)
  4. Call applyTheme(d.theme) and sync the color picker input values to the loaded theme
  5. Show a success toast
Fix collectData()

The collectData() function must output the exact unified schema from Step 2. Update all field names to match. The output must include:

  • name, title, about, theme, contact, profile
  • experience, education, skills, languages, references
  • footer with text and socials
  • Any optional sections the template uses: projects, awards, stats, hero
Sticky Action Bar

Must contain these three buttons in order:

  1. Load JSON — file picker, loads and populates all fields
  2. Generate & Download — validates name, downloads data.json
  3. Preview — opens index.html#data=<encoded JSON> in a new tab

All three must be visible on the form.html page regardless of online/offline status — Load JSON on the form builder is always shown (unlike on index.html).

Toast Notifications

If not already present, add a small fixed toast element (bottom-right, z-index above action bar). Shows for ~3 seconds on: load success, download success, validation error. Styled with the template's accent color as a left border.

Hamburger

Must use the same implementation as index.html — class-based toggle, ☰ ↔ ✕ icon, outside-click close, link-tap close.

STEP 06Sample Data & File Output
▾
Update data.json

Rewrite the template's data.json to conform to the unified schema in Step 2. Keep the same fictional persona (same name, same career field, same general content) but restructure the keys and add any missing top-level fields. Specifically:

  • If personalInfo.firstName/lastName was used, flatten to name
  • If socialLinks was at the top level, move it to footer.socials
  • Add theme object if missing — choose colors that match the template's visual style
  • Add profile object with image and eyebrow if missing
  • Add references array if missing — create 2 realistic fictional references
  • Add languages array if missing
  • Add footer object with text (containing {year}) and socials if missing
  • Add any optional sections (projects, awards, stats) if the template's index.html renders them
File Output
  • Deliver the updated index.html, form.html, and data.json
  • Keep all original assets/ folder contents unchanged
  • Package as a .zip and present as a download, plus individual file previews
  • All CSS and JS must remain inline — no separate stylesheet or script files
Do Not Change
  • The visual design, color palette, fonts, or layout structure
  • The persona's name, career field, or content (only restructure the data keys)
  • Any section that already works correctly and follows the standard
