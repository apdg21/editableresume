Redesign Prompt

A comprehensive prompt for redesigning resume and portfolio HTML templates — covering design rules, features, offline/online behaviour, and quality checks.

7 Steps

STEP 01 Read the Files First
▾

Before writing any code, extract and read every file in the zip:

  • index.html — the main resume/portfolio page
  • form.html — the data entry / builder page
  • form.js / main.js — all JavaScript logic
  • data.json — the data structure and field names
  • style.css — original styles (for reference only, do not reuse)

Understand the full data structure, all sections rendered, all dynamic fields in the form, and every piece of functionality before proceeding.

STEP 02 Design Rules
▾

Create a completely new design. It must be visually distinct from these previously used styles:

  • Style 1 — Dark editorial: black/charcoal with gold accents, DM Serif Display + Syne
  • Style 2 — Dark glass: deep green gradient, frosted glass cards, Fraunces + Plus Jakarta Sans
  • Style 3 — Dark cosmic: deep indigo gradient, star-field texture, Instrument Serif + Outfit
  • Style 4 — Light airy: warm cream/sage gradient, fixed sidebar, Cormorant Garamond + DM Sans
  • Style 5 — Light terracotta: warm linen gradient, single-column, Playfair Display + Inter

Pick a direction that hasn't been used. Some ideas: bold brutalist, soft pastel minimal, high-contrast monochrome, magazine editorial, Swiss grid, neon-accent dark, warm newspaper, cool nordic, rich jewel tones. You decide — just make it fresh, modern, and beautiful.

Design requirements:

  • Use a gradient background (linear-gradient, background-attachment: fixed) — store the two gradient colors and accent color in CSS variables so they can be changed at runtime
  • Use Google Fonts — pick a pairing that fits the aesthetic (one serif or display + one sans-serif)
  • All text must be readable — maintain sufficient contrast on every element
  • Use subtle texture overlays (CSS feTurbulence SVG filter or radial-gradient dot/star patterns) for depth
  • Cards, sections, or panels should use backdrop-filter: blur or soft box shadows — not flat solid boxes
  • Must be fully responsive: desktop, tablet, and mobile
  • Smooth scroll, fade-in on scroll via IntersectionObserver, active nav link highlighting on scroll
STEP 03 New Sample Data
▾

Replace the sample data in data.json with a completely different person. Requirements:

  • Different name (Filipino or international — vary it)
  • Different job/career field from all previous designs (previous fields used: UX Designer, Environmental Scientist, Aerospace Engineer, Nutritionist/Dietitian, Financial Analyst)
  • Realistic, detailed content — proper job titles, company names, responsibilities, education, skills
  • Philippine context is fine but not required — vary the location too
  • All fields in the original data.json structure must be present and populated
  • Include a theme object in data.json with gradientStart, gradientEnd, and accentColor so the index page applies the correct colors on load
STEP 04 index.html Requirements
▾

Rebuild index.html from scratch. Keep every section the original had. Add or improve sections if it makes sense.

Navigation:

  • Fixed top navbar (or fixed sidebar on desktop if the layout suits it)
  • Logo/brand shows the person's name (populated from data.json)
  • Nav links scroll to each section; active link highlights on scroll
  • On mobile: nav links collapse, a hamburger button appears
  • Hamburger must work correctly: clicking toggles the mobile menu open/closed, icon changes from ☰ to ✕ when open, clicking any nav link closes the menu, clicking anywhere outside the menu closes it. Use a class toggle (e.g. .open) — never use style.display toggling directly on the nav list

Offline-only elements — THE MOST IMPORTANT RULE:

The following elements must be hidden when deployed (served over http:// or https://) and only visible when opened locally as a file (file:// protocol):

  • "Load JSON" button (for uploading a data.json file manually)
  • "Edit" navigation link (linking to form.html)
  • Any equivalent mobile menu versions of the above

Implementation — do this exactly:

  • Add class="offline-only" AND style="display:none" (inline) to every one of these elements in the HTML. The inline style ensures they are hidden before any JavaScript runs, preventing a flash of visible content on page load.
  • In the JavaScript, detect the protocol: const isLocal = location.protocol === 'file:';
  • Only if isLocal is true, reveal them: if (isLocal) document.querySelectorAll('.offline-only').forEach(el => el.style.display = '');
  • Never conditionally hide them — only conditionally show them. Default is always hidden.

Data loading:

  • On load, fetch('data.json') — if it succeeds, render the resume
  • If fetch fails, check for a #data= URL hash (used by form.html preview) and try to parse and render that
  • If both fail, show a centered upload overlay/modal where the user can select their data.json file
  • The upload overlay must have a link to form.html for users who don't have a data file yet

Theme application:

  • Read data.theme.gradientStart, data.theme.gradientEnd, and data.theme.accentColor from the loaded JSON
  • Apply them to CSS variables at runtime using document.documentElement.style.setProperty()
  • Also update document.body.style.background directly so it overrides the default
  • Derive secondary accent values (dim, glow, rgba variants) from the accent hex using a hexAlpha(hex, alpha) helper function

No Download PDF button — do not include a PDF download button on index.html unless explicitly requested.

STEP 05 form.html Requirements
▾

Rebuild form.html from scratch. It must match the visual design of index.html exactly — same fonts, same gradient background, same card styles, same button styles.

Navigation: Same fixed navbar as index.html but with a "Builder" badge instead of the Load JSON / Edit buttons. Links to index.html and anchor links to major form sections. Same working hamburger with mobile dropdown.

Theme / Background Color Picker section — required in every redesign:

  • A dedicated card/section titled "Background Theme" or similar
  • 8 preset swatches: circular gradient buttons the user can click to instantly apply a preset theme. Each preset has g1 (gradient start), g2 (gradient end), and ac (accent color). Each swatch shows a small colored dot representing the accent color.
  • 3 manual color pickers: one each for Gradient Start, Gradient End, and Accent Color. Each picker has both an <input type="color"> and a synced hex text input next to it so users can type exact values.
  • Live preview bar: a thin horizontal gradient strip that updates in real time as colors change, showing gradientStart → accent → gradientEnd
  • Clicking a preset activates it (adds .active class), deselects all others, and updates both the pickers and the live page background instantly
  • Manually changing a color picker deselects all presets
  • All changes apply live to the form page background and accent color

Form sections:

  • Recreate every section that existed in the original form.js / form.html — do not remove any fields
  • Use dynamic add/remove cards for repeating sections (experience, education, skills, languages, references, social links, etc.)
  • Each dynamic card has a styled "Remove" button
  • "Add [Item]" buttons at the bottom of each section

Action bar (sticky bottom):

  • Load JSON — opens a file picker to load an existing data.json, populates all form fields
  • Generate & Download — collects all form data, validates that name is filled, creates and downloads data.json
  • Preview — opens index.html#data=<encoded JSON> in a new tab so the user can see the result without downloading

Load JSON functionality:

  • When a JSON file is loaded, clear all dynamic containers first, then repopulate every field
  • Also read data.theme and apply it to the form background via applyTheme()
  • Show a toast notification on success or error

Toast notifications: Small notification that slides up from the bottom-right, shows success/error messages, auto-dismisses after ~3 seconds, styled with accent color left border.

Data collection: collectData() function reads all form fields and returns a complete JSON object matching the exact structure of data.json. Include the current theme colors under data.theme. Validate required fields before generating.

STEP 06 File Output
▾

Produce these files:

  • index.html — complete, self-contained (no external CSS files)
  • form.html — complete, self-contained (no external CSS files)
  • data.json — new sample data for the new person
  • Keep any original assets/ folder contents (profile photo, images)

Package everything into a .zip file and present it as a download along with the individual HTML files for preview.

STEP 07 Quality Checklist
▾

Before finishing, verify every item below. Click to check off as you review.

  • All .offline-only elements have both class="offline-only" AND style="display:none" in the HTML
  • The JS only shows them if location.protocol === 'file:' — never hides them via JS
  • Hamburger works: toggle icon, outside-click close, closes on link click
  • form.html theme picker live-updates the page background and accent color
  • data.json has a theme object with gradientStart, gradientEnd, accentColor
  • index.html applies the theme from data.json on render
  • form.html Load JSON repopulates every field including dynamic ones
  • Preview button passes data via URL hash and index.html reads it as fallback
  • Upload overlay shows when data.json fails to load and hash fallback also fails
  • No Download PDF button unless asked
  • Mobile is fully usable — no horizontal scroll, readable text, tappable buttons
  • Design is visually distinct from all 5 previous styles listed above
  • Sample data is a completely new person with a different career field
