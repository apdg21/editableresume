STEP 01 Project Overview
▾

You are building a brand-new HTML/CSS/JS resume or portfolio template completely from scratch — no base template is provided. The result must be a polished, modern, fully functional resume website that anyone can use by dropping in their own data.json file.

The deliverables are:

  • index.html — the public-facing resume/portfolio page (self-contained, no external CSS files)
  • form.html — the data builder/editor page (self-contained, no external CSS files)
  • data.json — sample data for a realistic fictional person
  • An assets/ folder with a placeholder or sample profile photo
  • Everything packaged as a .zip for download

All HTML, CSS, and JavaScript must be written inline inside each file. No separate style.css or main.js files.

Design requirements (all mandatory):

  • Use a gradient background (linear-gradient, background-attachment: fixed). Store both gradient stop colors and the accent color in CSS variables at :root so they can be changed at runtime via JavaScript
  • Use Google Fonts — choose one display/serif font and one sans-serif that complement the aesthetic
  • Use a subtle texture overlay — either a CSS feTurbulence SVG filter (noise), or radial-gradient dot/star patterns — applied as a fixed body::before pseudo-element
  • Cards, panels, or section containers must use backdrop-filter: blur or soft layered box shadows — no flat solid-color boxes
  • All text must pass a basic contrast check against its background — both in the default theme and when an alternate preset is applied
  • Must be fully responsive: comfortable on desktop (1200px+), tablet (768px), and mobile (360px)
  • Include smooth scroll behavior, scroll-triggered fade-in animations via IntersectionObserver, and active nav link highlighting as the user scrolls
STEP 03 Data Structure (data.json)
▾

Design a clean, logical data.json structure that covers all the sections you plan to include. At minimum it must contain:

  • Personal info — name, job title, email, phone, location, profile image path
  • About / summary — a paragraph or two of professional bio
  • Work experience — array of jobs, each with company, role, dates, and bullet-point responsibilities
  • Education — array of degrees/certifications with institution, dates, and description
  • Skills — can be a flat list of strings, or objects with name and level (0–100), or grouped by category — choose what fits the design
  • Languages — list of languages with proficiency level or label
  • References — array of references with name, role, phone, email
  • Social links — array of platform + URL pairs
  • Footer — copyright text, social links
  • Theme object — gradientStart, gradientEnd, accentColor — used to apply colors when the JSON is loaded

You may add extra sections (certifications, projects, awards, publications, portfolio items, etc.) if they suit the sample persona. Keep field names consistent between data.json, main.js/index.html render logic, and form.html collect logic.

Sample persona rules:

  • Create a realistic fictional person — not a generic placeholder
  • Use a career field not yet used in this collection (previous: UX Designer, Environmental Scientist, Aerospace Engineer, Nutritionist, Financial Analyst)
  • Write full, realistic content — actual responsibilities, real-sounding company names, specific achievements with numbers where possible
  • Vary nationality, location, and cultural context from previous templates
  • The persona's name and job should be reflected in the page <title> tag
STEP 04 index.html — Resume Page
▾
Navigation
  • Fixed top navbar or fixed sidebar — whichever suits the layout
  • Brand/logo shows the person's name, loaded from data.json
  • Nav links that scroll to each section on the page
  • Active link highlights as the user scrolls using a scroll event listener
  • On mobile, desktop nav links collapse and a hamburger button appears
Hamburger Menu (exact implementation)
  • Clicking the hamburger toggles an .open class on a separate mobile dropdown element
  • The hamburger icon switches from ☰ to ✕ when open (toggle a class on the button, transition the bars with CSS transforms)
  • Clicking any link inside the mobile menu closes it
  • Clicking anywhere outside the menu and hamburger button closes it
  • Never use style.display toggling directly on the nav list — always use class toggling
⚠ Offline-Only Elements — Most Important Rule

These elements must be hidden when deployed (on http:// or https://) and only visible when opened locally from the filesystem (file://):

  • The "Load JSON" button
  • The "Edit" navigation link (to form.html)
  • Any mobile menu equivalents of the above

Exact implementation — do not deviate:

  • Every offline-only element must have BOTH class="offline-only" AND style="display:none" written directly in the HTML attribute. This prevents a flash of visible content before JS runs.
  • In CSS: .offline-only { display: none; } — as a safety net
  • In JS: const isLocal = location.protocol === 'file:';
  • Then: if (isLocal) document.querySelectorAll('.offline-only').forEach(el => el.style.display = '');
  • Never hide them conditionally — the default state is always hidden, and JS only reveals them
Data Loading Flow
  • fetch('data.json') on page load — on success, call render(data)
  • On fetch failure, check location.hash.startsWith('#data=') — if found, JSON.parse(decodeURIComponent(location.hash.slice(6))) and render (this is the preview path from form.html)
  • If both fail, show a full-screen upload overlay modal
  • The upload overlay has a "Select File" button that opens a file picker, and a link to form.html for users who haven't created their data yet
Theme Application
  • After loading data, call applyTheme(data.theme)
  • Use document.documentElement.style.setProperty('--ac', data.theme.accentColor) etc. for each variable
  • Set document.body.style.background directly as a fallback override
  • Include a hexAlpha(hex, alpha) helper that converts a hex color to rgba(r,g,b,alpha) — use it to generate --ac-dim and --ac-glow from the accent color
Content Sections (include all that fit the data structure)
  • Hero / header — profile photo, name, title, contact chips
  • About / summary paragraph
  • Work experience — timeline or card list
  • Education — timeline or card list
  • Skills — progress bars, pills, dot bars, or categorised cards
  • Languages — proficiency indicators
  • References — contact cards
  • Contact section — icons + details
  • Footer — copyright text + social icon links
  • Any extra sections that suit the persona (projects, awards, certifications, etc.)

No Download PDF button — do not include one unless explicitly asked.

STEP 05 form.html — Builder Page
▾

form.html must be visually identical to index.html — same fonts, same gradient, same card style, same button aesthetic. A user should immediately recognise they are in the same product.

Navigation
  • Same fixed navbar, but replace the Load JSON / Edit items with a "Builder" or "Editor" badge
  • Include a link back to index.html (View Resume / View Portfolio)
  • Anchor links to major form sections for quick navigation
  • Same working hamburger with mobile dropdown — identical behavior to index.html
Theme / Background Color Picker — Required in Every Build
  • A dedicated section card titled "Background Theme" or similar
  • 8 clickable preset swatches — circular buttons, each showing a gradient preview with a small accent-color dot. Clicking one instantly applies that theme to the form page background and accent color
  • 3 manual color pickers — one each for Gradient Start, Gradient End, and Accent Color. Each has an <input type="color"> and a synced hex text input side by side
  • Live preview strip — a thin bar below the pickers showing gradientStart → accent → gradientEnd, updating in real time
  • Selecting a preset marks it .active and deselects all others; manually adjusting a picker deselects all presets
  • All theme changes apply live to the form page itself so the user sees exactly what the resume will look like
Form Sections
  • Every field that exists in data.json must have a corresponding input in the form
  • Repeating sections (experience, education, skills, languages, references, social links, etc.) use dynamically added cards — a JS function generates and appends a new card on "Add" button click
  • Each dynamic card has a "Remove" button that removes that card from the DOM
  • An "Add [Item]" button sits below each repeating section
  • Input fields use the theme's surface color as background, with clear uppercase small-caps labels, and an accent-color focus glow
  • Use a two-column grid for short paired fields (start/end dates, first/last name, etc.) and single-column for text areas
Sticky Action Bar
  • Fixed to the bottom of the viewport, always visible
  • Contains three buttons in this order:
    1. Load JSON — triggers a hidden <input type="file">, reads the selected JSON, populates all fields, applies theme
    2. Generate & Download — collects all data, validates name field, creates and downloads data.json
    3. Preview — opens index.html#data=<URL-encoded JSON> in a new tab
Load JSON Behaviour
  • Clear all dynamic container elements first (innerHTML = '')
  • Repopulate every static field (name, title, about, contact, etc.)
  • Re-run the "add" function for each item in every repeating array (experience, education, etc.)
  • Call applyTheme() with the loaded theme values and update the color picker inputs
  • Show a success toast on completion
Toast Notifications
  • A small fixed element, bottom-right, hidden by default
  • Slides up and fades in when shown, auto-hides after ~3 seconds
  • Styled with the theme accent color as a left border
  • Used for: "✓ Data loaded", "✓ data.json downloaded", and error messages
collectData() Function
  • Reads every form field and builds a complete object matching data.json exactly
  • Includes theme object with the current picker values
  • For repeating sections, use querySelectorAll with a class selector and map over the results
  • Validates that the name field is non-empty before allowing generate or preview
STEP 06 Layout Patterns & Sections
▾

Choose a layout pattern that fits your design direction. Here are common options — pick one and commit to it:

  • Single-column centred — all content in one max-width column, sections separated by dividers or whitespace. Clean and readable, works for minimalist or editorial styles.
  • Fixed sidebar + scrolling main — a narrow fixed left sidebar holds the profile photo, name, nav links, and contact info; the right column scrolls with all sections. Good for airy or professional styles.
  • Two-column split hero — hero section is a 50/50 or 60/40 split with text on one side and photo/illustration on the other; subsequent sections stack full-width below.
  • Card grid — sections displayed as cards in a responsive grid, especially effective for skills, projects, and references.
  • Timeline layout — experience and education rendered as a vertical timeline with date labels on one side and content on the other; a vertical rule connects the items.

Section design notes:

  • Every section needs a clear visual section header — a combination of an eyebrow label (small-caps uppercase), a main title (serif or display font), and a decorative rule or divider
  • Animate each section card/container into view using IntersectionObserver — start at opacity: 0; transform: translateY(20px) and transition to visible when it enters the viewport
  • Skill progress bars must animate their width from 0 to the target value when their container becomes visible — trigger this inside the IntersectionObserver callback
  • Profile photos: use a rounded or circular crop with a border or glow in the accent color
  • Contact info: render as pill-shaped chips or icon + text rows — not bare text
  • Social links in the footer: icon-only circular or square buttons with hover state
STEP 07 File Output & Delivery
▾

Produce and deliver the following:

  • index.html — complete resume page, all CSS and JS inline, no external dependencies except Google Fonts CDN and Font Awesome CDN
  • form.html — complete builder page, same inline approach
  • data.json — realistic sample data for the fictional persona, including the theme object
  • assets/profile.jpg — use the provided profile photo if one was given; otherwise note that a placeholder should be placed here

Package all files into a .zip archive. Present the zip as a download, then also present index.html and form.html individually as previews.

Allowed external CDN links (these are fine to reference):

  • Google Fonts via https://fonts.googleapis.com
  • Font Awesome via https://cdnjs.cloudflare.com/ajax/libs/font-awesome/
  • No other external scripts, stylesheets, or frameworks
STEP 08 Quality Checklist
▾
Before finishing — verify every item

Click each item to check it off as you review the output.

  • Every .offline-only element has BOTH class="offline-only" AND style="display:none" written in the HTML
  • JS reveals offline-only elements only when location.protocol === 'file:' — it never hides them
  • Hamburger toggles correctly: ☰ → ✕ icon, opens/closes menu, closes on outside click, closes on link tap
  • data.json has a theme object with gradientStart, gradientEnd, accentColor
  • index.html reads and applies the theme from data.json on render via CSS variable updates
  • index.html falls back to #data= URL hash if fetch('data.json') fails
  • Upload overlay is shown when both fetch and hash fallback fail, with a link to form.html
  • form.html theme picker has 8 preset swatches, 3 manual pickers with hex inputs, and a live preview bar
  • Preset swatches update the page background and accent color live when clicked
  • Manual color pickers update live; manually adjusting deselects all preset swatches
  • Load JSON in form.html clears all dynamic containers and repopulates every field and section
  • Load JSON also calls applyTheme() and updates the picker input values
  • Preview button encodes all form data into index.html#data=... and opens it in a new tab
  • Generate & Download validates name field before creating the file
  • Toast notifications appear for load success, download success, and errors
  • Skill bars animate from 0 to their value when their section scrolls into view
  • All sections fade/slide in using IntersectionObserver
  • No Download PDF button included (unless explicitly requested)
  • Mobile layout is fully usable — no horizontal scroll, text is readable, buttons are tappable
  • Design is visually distinct from all 5 previously used styles
  • Sample data uses a completely new person with a different career field from previous templates
  • All CSS and JS is inline in each file — no separate stylesheet or script files
  • Files are packaged in a .zip and presented as download + individual previews
